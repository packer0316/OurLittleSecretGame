# 說好不說 — We Promised Not to Tell

OurLittleSecretGame v0.2。Three.js 第一人稱台灣民俗懸疑遊戲，包含住處／山村序章、四章寺廟主線、十一組證據與三種結局。新版「未播完的錄音」從朋友寄回的照片開始。當晚，他在電話裡重複了同一句話。

## 開始遊戲

Windows 雙擊 **start.bat**；或在專案資料夾執行：

```powershell
npm install
npm run dev -- --open
```

一般網址為 `http://localhost:5173/`，終端機會顯示實際連接埠。本次驗證伺服器使用 `http://127.0.0.1:5178/`。不同網址、連接埠與瀏覽器的本機存檔互相獨立。

專案已附本次圖片與模型。`npm run assets` 可重新取得既有 Poly Haven 素材；正式發布輸出使用 `npm run build`，產物在 `dist/`。遊戲執行不會連接外部素材站。

## 內容與場景

- **住處序章「未播完的錄音」**從照片與阿哲的來電開始。門外敲了三下，玩家第一次決定要不要應。門把、門縫光和椅子都有場景演出。
- **山村序章「沒有人等車」**沿電池盒、住戶公告、作坊與攝影機追蹤阿哲的路線，並在公告上第一次讀到「借聲」和「門外有人喊名，勿應」。
- **第一章「還亮著的燈」**確認正殿器材與關閉的山門。山門告示背面是借聲的舊規矩。
- **第二章「多應了一聲」**比對計數器、門閂和錄音：點名點到六，門從外面扣上，錄音在 02:47 被剪斷。可額外調查三槽木盤。
- **第三章「未播出的片段」**在戲台看見第六聲「有」是誰喊的，沿回廊的彈珠與紅線找路，再擲筊問路。
- **第四章「把最後一句說完」**以阿哲的手機、身高刻痕、布兔、名牆與地下舊鎖，補齊被剪掉的那一分鐘。
- **三種結局**由最後選擇及調查完整度決定，並會記得玩家應過幾次、被追上幾次、怎麼對佩珊說話。筆記與目標欄不會提前顯示未取得線索的名稱。
- **可選讀物**三件（阿哲的清點日誌、郭師父的規矩簿、門前的女鞋）不計入十一組證據，讀過後可從筆記重看。


慈雲寺有四層可走動樓層、廟埕、古戲台、亂葬崗與地下封印室。地面樓梯連續可走；地下入口以帶有字幕的轉場移動，南側可返回四樓。

主尊改用博物館掃描模型，全部完整佛像維持蒙眼紅布。另有燭蠟、長布幔、潮濕 PBR 材質、看不見時轉頭的佛像、可追逐的骨架女影、紅布兔、送魂供桌與刻名手印牆。真結局後光線轉暖、恐怖環境聲停止，童年記憶剪影抱兔消散。

三張地圖都由恐怖導演（`src/horror/`）安排環境驚嚇：轉身時出現又消失的人影、移開視線就靠近一截、柱後探頭、光圈邊緣的赤腳、熄滅的手電筒、身後逐盞熄滅的燭火、走向你的濕腳印、跟著腳步的敲擊、電視倒影與窗外的臉、會趁你沒看時轉頭的佛像與紙紮人，另有八種只有聲音的假警報。進入地圖的前一分多鐘只有輕微事件，之後依章節升級。

## 驗證

```powershell
npm test
npm run build
# 另開終端啟動測試伺服器
npm run dev -- --host 127.0.0.1 --port 5178 --strictPort
# 測試終端
npm run test:story
node scripts/narrative-loop.mjs
$env:GAME_URL = 'http://127.0.0.1:5178/?auto&map=temple'
npm run test:walk
```

需安裝 Google Chrome；使用專案的 playwright-core。

- `story-state.test.mjs`：證物順序、真結局門檻、存檔與損毀資料、可選讀物白名單、目標欄不洩漏未取得證物的名稱。
- `story-causality.mjs`：規矩先說再考、應門會被記住、三件可選讀物可用 E 讀取且不計入證據、戲台證物頁、佩珊聲音的呼名、結局記得玩家的選擇、提示光點不閃爍。
- `story-smoke.mjs`：四章、十一證物、實際 E 鍵調查、送魂供桌、真結局。
- `story-branches.mjs`：追逐、安全區、死亡重試、普通／替身結局、存讀檔、暫停、倒數與模型匯出。
- `story-ui.mjs`：正常標題進入、滑鼠鎖定、筆記、暫停、回大廳續玩、素材本機載入、小尺寸文件。
- `walktest.mjs`：樓梯、入口、圍牆碰撞、戲台階梯與地下回程。
- `home-loop.mjs`：住處六段互動、WASD 行走、三份可選筆記、存讀檔與進入山路。
- `road-loop.mjs`：使用實際 WASD 走完停車處、石橋、村落、作坊、回程與進寺，並驗證路途中存檔。
- `prelude-continuity.mjs`：佩珊回電、畫質切換、正常選單續玩山村、正常滑鼠鎖定換場到寺廟、序章筆記與真結局回應。
- `door-event.mjs`：門縫字條的實際滑動、三次敲門、靠近才觸發、閱讀／暫停停止事件及中途讀檔。
- `desk-fixes.mjs`：信件手寫字型、照片塗痕對位、點擊／Enter／數字 1 放置照片與自動開啟閱讀。
- `input-phone-loop.mjs`：原生滑鼠轉向、鎖定切換、異常位移防護、來電亮屏、低畫質、讀檔與接聽／掛斷；截圖在 `artifacts/input-phone-loop/`。
- `horror-events.mjs`：三張地圖逐一觸發恐怖導演的每個環境事件並截圖；`horror-fixed.mjs`：固定人影、追逐、被抓到的衝臉、住處敲門與拖椅；`horror-mechanics.mjs`：轉身鬼等核心機制照正式條件運作、首次現身不卡頓、換地圖清理、回退模式；`horror-soak.mjs`：開著環境事件模擬數分鐘遊玩，檢查節奏與每幀成本。截圖在 `artifacts/horror/`。
- 效能量測（輸出在 `artifacts/perf/`）：`perf-scene.mjs`（三張地圖的載入時間、傳輸量、draw call／三角形、各視角整幀成本）、`perf-walk.mjs`（沿固定路線的影格時間與 GPU 時間、卡頓次數）、`perf-hitch.mjs`（巡場與鬼現身時不得臨時編譯 shader／上傳貼圖／建立幾何）、`perf-travel.mjs`（換場時間與資源釋放）、`perf-feel.mjs`（貼牆滑行、樓梯、蹲下、手電筒陰影排程）、`perf-ab.mjs`（開關最佳化的畫面逐像素比對）。網址加 `?noopt` 可關閉點光源池、遮蔽物深度預畫、動態解析度、解析度上限、載入暖機與手電筒陰影排程，供前後對照；`?auto` 預設不啟用動態解析度，加 `&drs` 才啟用。

截圖與 JSON 結果保存在 `artifacts/story/`。流程測試使用指定站位來隔離驗證互動，行走另外測試；不是全程真人試玩的替代品。測試環境（Intel 內顯、1440×900、中畫質）沿寺廟固定路線的 GPU 時間平均約 10 ms、各視角整幀成本 8–14 ms；不保證其他硬體達到相同幀率。內部解析度有像素上限，影格時間超出預算時會自動降低（最低 60%），首次遊玩若仍不足會自動改用低畫質。

`npm run build` 不會把執行時用不到的來源檔複製進 `dist/`（三個可重用 GLB 匯出成品，以及已另存 WebP 或未使用的劇情 PNG；清單在 `vite.config.js`），檔案仍保留在 `public/`。PNG 更新後以 `python scripts/perf-images.py` 重新產生 WebP。

開發快捷鍵需在網址加 `?dev`：L 全亮、V 飛行、P 座標、1–7 傳送。正式預設不開啟。`?auto&map=temple` 是自動測試入口。

隨機的環境驚嚇（恐怖導演）在 `?auto` 下預設關閉，測試才有確定的狀態；加 `&horror` 啟用、`&hseed=數字` 固定亂數、`&nohorror` 在一般遊玩時關閉。主控台可用 `__game.horror.debug`：`list()` 列出這張地圖的事件、`trigger(id)` 直接觸發、`state` 看 dread／節奏階段／進行中的事件、`hold = true` 凍結以便截圖。

## 程式入口與備份

`src/story/campaign.js` 是章節／證物資料，`src/story/Story.js` 管理對話、儀式與存檔；`src/maps/temple/storyWorld.js` 建構敘事陳設，`buddha.js` 與 `ghost.js` 處理模型。`src/horror/` 是恐怖導演：緊張度與「鋪陳 → 逼近 → 爆發 → 喘息」的節奏（`director.js`）、轉身鬼與環境異變（`events/`）、跟著劇情的固定演出加強（`reactive.js`）；它只輪詢劇情狀態，不改 Story。

本次編輯前的程式、首頁、樣式與 README 已保存在 `backups/before-story-redesign-20261113/`。所有開發均在使用者指定的 D 槽專案。
